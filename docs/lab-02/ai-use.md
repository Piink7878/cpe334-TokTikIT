# Lab 2 — AI Use and Reflection

**LLM/agent used:** Google Cloud Platform's Antigravity (Gemini 3.1 Pro - High)

## Selected key prompts (8)

| # | Prompt | Reflection |
|---|--------|------------|
| 1 | ช่วยอ่าน requirement ของ Lab 2 ให้หน่อย สรุปมาว่าต้องเพิ่มตารางอะไรใน Prisma บ้าง แล้วเรียงลำดับการทำงานมาให้ดูหน่อยว่าควรเริ่มจากตรงไหนก่อน | ได้แผนการทำงานที่ชัดเจนมาก ช่วยให้มองเห็นภาพรวมว่าต้องเพิ่มโมเดล Ticket กับ Requester ก่อนที่จะไปทำส่วน API |
| 2 | ช่วยอัปเดตไฟล์ schema.prisma ให้ที เพิ่มโมเดล Ticket กับ Requester ตามที่เราคุยกันไว้ตอนแรก แล้วอย่าลืมตั้งค่าความสัมพันธ์ของตารางด้วยนะ | โค้ดที่ได้มาถูกต้อง สามารถนำไปรัน migrate สร้างฐานข้อมูลได้ทันทีโดยไม่ติดปัญหาอะไร |
| 3 | ทำ API สำหรับสร้าง Ticket ใหม่ให้หน่อย (POST) เอาแบบที่รับข้อมูลจากฟอร์มแล้วบันทึกลงฐานข้อมูลได้เลย อ้อ ถ้าผู้ใช้ส่งข้อมูลมาไม่ครบให้คืนค่า error 400 กลับไปด้วยนะ | API ทำงานได้ตามที่สั่ง มีการดักจับ error ได้ดี แต่ต้องไปแก้โค้ดฝั่ง frontend นิดหน่อยตอนส่งข้อมูลให้ field ตรงกัน |
| 4 | สร้าง API ดึงข้อมูลคนแจ้งซ่อม (Requester) ให้หน่อย ขอเฉพาะคนที่ยังมีสถานะ active อยู่นะ แล้วก็ให้เรียงลำดับตามชื่อด้วย จะเอาไปใส่ใน dropdown | ได้ผลลัพธ์มาตรงเป๊ะ เอาไปเชื่อมกับ component dropdown ใน React ได้ง่ายและประหยัดเวลาไปได้เยอะ |
| 5 | ตอนนี้ถ้าข้อมูล Ticket มีเยอะ หน้าเว็บมันน่าจะโหลดช้า ช่วยทำ Pagination ให้ API ดึงข้อมูล Ticket หน่อย ให้ส่งข้อมูลกลับมาทีละ 10 รายการ และบอกมาด้วยว่ามีกี่หน้า | AI ทำเรื่อง limit กับ offset ใน Prisma มาให้ครบถ้วน แถมยังส่ง meta data กลับมาให้ฝั่ง frontend เอาไปทำปุ่มเปลี่ยนหน้าได้เลย |
| 6 | ฝั่ง frontend มันขึ้น error ว่า `Parameter 'att' implicitly has an 'any' type` มันหมายความว่ายังไง ช่วยอธิบายและแก้ให้หน่อย | ได้เรียนรู้เรื่องการกำหนด Type ใน TypeScript มากขึ้น AI ไม่งงและช่วยเติม interface ให้ ทำให้ error หายไปและโค้ดปลอดภัยขึ้น |
| 7 | ช่วยทำหน้าจอสำหรับแสดงรายการ Ticket ให้หน่อย โดยให้ดึงข้อมูลจาก API ที่เพิ่งทำไป จัดหน้าตาด้วย Bootstrap ให้ดูสะอาดตา มีสถานะบอกชัดเจน | ได้หน้าตา UI พื้นฐานที่ใช้งานได้จริง นำมาปรับแต่งเรื่องสีของ Badge สถานะและการจัดวางตารางต่ออีกนิดหน่อยเพื่อให้เข้ากับดีไซน์ |
| 8 | ช่วยเช็คโค้ด frontend และ backend ที่เพิ่งเขียนไปทั้งหมดของระบบ Ticket ให้หน่อยว่ามีตรงไหนที่ควรปรับให้โค้ดมันอ่านง่ายขึ้น หรือมีจุดไหนที่อาจจะเกิดบั๊กได้บ้าง | AI แนะนำให้แยกบางส่วนใน React ออกมาเป็น component ย่อย ทำให้โค้ดโดยรวมอ่านง่ายขึ้นและจัดการได้ดีกว่าเดิม |

## Reflection
จากการทำงานในแล็บนี้พบว่า การคุยกับ AI แบบเป็นธรรมชาติและค่อยๆ สั่งงานไปทีละส่วน ช่วยลดความผิดพลาดได้ดีกว่าการพยายามเขียน prompt ที่รวบยอดทุกอย่างในครั้งเดียว นอกจากนี้การให้ AI ช่วยอธิบาย error ต่างๆ ยังช่วยให้เราเข้าใจโค้ดของตัวเองและ TypeScript ได้ดีขึ้นอีกด้วย
